Search/planning integration with member lifecycle

Integrated team baseline: 823efd5ebced1dd91a6627ee7881db0a9c67d175 (merged PR #116). Fork branch: duynguyen21007:search-and-planning; PR #109 targets team master. This is a local branch integration, not a merge of PR #109 into the team repository.

Conflict resolution

The five conflicts are resolved by retaining both owners' behavior:

  • User Guide includes search, member edit, soft-delete and restore (15 command routes).
  • MemberListCommand reports active/deleted counts and explicitly resets to an all-records query.
  • MemberCommandParser retains search, edit and restore, including all names in its diagnostic.
  • MemberListPanel uses filtered/sorted snapshots while retaining the real deleted-card styling.
  • MemberDirectorySummary shows filtered Displayed counts and independent active/deleted totals.

The incoming root/model/JSON/card/detail implementations and their tests are retained. No competing lifecycle fields or schema are introduced. Member search defaults to active records; status/deleted finds retained records for restoration, and status/all searches both states. List/reset still shows both states, as required by the merged member lifecycle contract. Additional eligibility predicates compose with the requested status. Equipment has no lifecycle metadata on this baseline, so its existing eligibility extension remains unchanged.

Deleted members are excluded from possible-similarity warnings; exact identity reuse remains rejected by the domain. Deletion/restoration reevaluates active queries and counts without destroying records. The earlier correction distinguishing plain navigation from an explicit list/reset is preserved.
