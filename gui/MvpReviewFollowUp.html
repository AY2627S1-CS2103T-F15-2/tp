Multiline notes through the full input path

The top-level AddressBookParser now accepts multiline arguments instead of rejecting them before the Laplace field validators run. The existing argument reader still enforces reserved markers and reports unknown/repeated/missing fields normally. It does not treat separate lines as separate command executions.

CommandBox installs a TextFormatter before JavaFX's single-line TextField content filtering. Pasted tabs and vertical-whitespace characters become spaces instead of being removed and joining words. Each input character keeps its offset, including the two characters in CRLF. Existing field normalization collapses those runs to one space before validation/storage. Selection replacement, caret position and undo/redo remain correct. Rejected pasted commands remain visible/focused for correction.

  • CommandBoxTest.multilineReplacement_preservesWordBoundariesCaretAndUndo checks replacement at a selected range, stable caret/anchor and undo/redo.

Feedback required by the detailed MVP specification

The existing commands capture the stored record and current open-loan context before attempting mutation. The model still owns deletion/loan policy. LogicManager's snapshot/atomic-save/publish boundary is unchanged. Inconsistent injected model state gets an explicit fallback rather than a fabricated holder ID.
