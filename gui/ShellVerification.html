Laplace shell verification

This implements issue #91 around the components now available on team master 0efb388f8a0daa180481dc6f049705bbd9a93add (merged details, loans and all ten routes). The window mounts the real member/equipment lists, cards, summaries, MemberDetailsPanel, EquipmentDetailsPanel, Loans panel and legacy Persons list. The shell does not modify those owned components or change their command routers; it consumes the merged implementations. ReviewResponse.md records all six review items and the open final acceptance tracker #75.

Behavior and ownership

The first screen is Members with the first sorted identity selected and the summary visible. The header has Members, Equipment and Loans buttons. Production startup now measures mounted panels before restoring the divider, matching UiManager's show-before-fill order. Directory columns start at 28%/72% and retain that proportion on resize. Feedback and command input remain below the scrollable content. The Menu exposes Help, legacy Persons and Exit; F1 opens Help even from command input. Saved window geometry is retained within the current screen's usable bounds.

Members and Equipment dispatch member list and equipment list through the same command pipeline as input. Loans opens its read-only panel directly. A row or loan identity link dispatches exactly member view nus/NUS_ID or equipment view uuid/UUID, once per explicit activation. Programmatic startup selection, selection restoration and refresh never dispatch commands. Row/link activation preserves its focus until its key finishes; shifting focus during Space previously inserted a stray space into command input. Navigation tabs still return focus to command input.

Navigation uses DisplayRequest, not feedback text. Help and Exit take precedence. An unchanged request retains the screen. Legacy commands still have their own Persons screen. Blank input is ignored; successful input clears; parse, command and save failures retain input for correction. Both success and failure have readable text, a status label and a different feedback background. Long feedback wraps and scrolls rather than expanding the command area offscreen.

The shell subscribes once to the live member, equipment, loan and filtered-person lists. Changes coalesce into one FX-event-loop refresh after a model operation. Refresh rebuilds related cards, holdings, availability, summaries and loan history, retaining identities and an explicitly empty selection. Deleting a selection chooses the next row at its former sorted position, or the last surviving row; an empty directory clears selection. Real detail fields refresh alongside cards/summaries/Loans, including while another tab is active. Removed detail identities leave stale detail mode and return to the corresponding summary. Disposal removes subscriptions and event handlers, and cancels queued refresh work.

A save failure does not imply rollback: the existing pipeline can mutate memory before saving. The shell shows the actual error, retains navigation/input and refreshes actual in-memory state.

Real routed integration

All ten family routes are active on this baseline. The transitional unavailable-view branch and its notice have been removed. Input, row activation and loan links now follow the same real typed results. Controlled results are retained only to test the display contract and an impossible/stale target.

The full real-command lifecycle adds two same-name members and two otherwise identical items with separate generated UUIDs, lists/views them, assigns both, verifies real holder/contact/notes/date and holdings fields, reloads a fresh model/logic/window from saved JSON, returns items, rejects repeated returns and open-loan deletion, deletes permitted identities, verifies deterministic selection/stale-detail cleanup, reloads again and repeats views. Every successful submitted command dispatches/saves exactly once.

Rejection cases interleave valid commands with duplicate/unknown identities, missing/repeated/unknown parameters, malformed dates/UUIDs, assigned/damaged/under-repair items, future assignment/return, expected-before-assigned, return-before-assigned and no-open-loan return. Each snapshots all four collections, current displayed panel, selected row and saved JSON bytes; failure preserves these, retains correction input/focus and never saves. Separate real-route external-update tests verify the coalesced refresh while member details, equipment details and Loans remain active without callback dispatches.

The supplied MVP document was checked against its "Laplace MVP Feature Specification" section. Its save-failure guarantee requires separate transaction work; the current test below remains a truthful report of the existing behavior. Completed history is still shown by Isaac's current LoanPanel despite being excluded by the newer MVP. Shared validation/normalization, UUID collision retry and the new member-held-item sort order also need their owners' updates. These dependencies are recorded in #75 and ReviewResponse.md; the shell tests do not certify full MVP compliance.

Tests and repeatable checks

Use Java 25 (sdk use java 25.0.3.fx-zulu on the configured macOS machine). The existing test runtime selects matching JavaFX 17.0.7 native jars. Run in a graphical session; Linux requires Xvfb.

./gradlew test --tests '*CommandBoxTest' --tests '*ResultDisplayTest' --tests '*MainWindowShellTest'
./gradlew check coverage shadowJar
./.github/run-checks.sh

The shell suite uses the actual MainWindow FXML, real components, ModelManager, LogicManager and JSON storage. It covers one-shot submission/activation, failure recovery, tab commands and Loans, typed requests, Help/Exit, selection recovery, root replacement, loan-only refresh, teardown, legacy contrast, geometry and saved-data reload. Controlled typed-result and disk-failure fixtures are identified separately in the test class. Tests fail on graphical errors and do not skip them.

The generated session record is build/reports/laplace/shell-session.txt. It records actual inputs, feedback, retained input, dispatched commands and save counts. Generated screenshots include normal/small Members, Equipment, both real details, Loans and legacy Persons, plus error, empty, missing and long-text states under build/reports/laplace/. These are snapshots of the actual mounted shell, rather than the earlier component preview fixture. The retained sessions are ShellSession.txt and RoutedShellSession.txt.
