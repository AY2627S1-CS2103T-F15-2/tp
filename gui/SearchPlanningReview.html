Search/planning review follow-up

This follow-up addresses both inline findings in PR #109's review of a7f752e7. The branch integrates team master 9885bb1e through merge commit 8a110cce.

Preserve queries after deletion

Plain directory requests from deletion and stale-detail fallback now preserve the active query. Only requests carrying criteria replace them. Member/equipment list commands explicitly carry DirectoryQuery.all() to reset filters and sorting. This keeps mutation navigation distinct from the user's deliberate reset command without introducing navigation inferred from feedback text.

Two real-shell regressions failed before the fix and passed afterwards:

  • Member deletion retains text/holding filters and descending ID sort, recovers selection when one match remains, and shows zero matches after the last matching member is removed.
  • Equipment deletion retains text/category/condition/availability filters and descending ID sort after the only matching unit is removed.

Both tests verify one dispatch/save per deletion, current JSON readback, summary counts/criteria, empty selection and the later explicit list reset. Existing list-command and routing tests now assert the explicit reset payload rather than a plain navigation payload.
