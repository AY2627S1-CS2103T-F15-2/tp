Delete a member

member delete nus/NUS_ID

Example: member delete nus/a0123456x

The individual parser and command are implemented. The application family route is still a placeholder on this PR's baseline; Duy owns its activation. These instructions specify the implemented component behavior, not a claim that typing the command already deletes members in the application. The shell and final acceptance remain under issues #74 and #75.

Input and behavior

Supply exactly one nus/ parameter. Leading/trailing spaces and tabs are accepted, and the NUS ID normalizes to uppercase using the existing value parser. Missing/blank IDs, repeated parameters, unknown markers and text before the first marker are rejected. Malformed IDs produce the existing NUS ID constraints. Row numbers and member names are not identifiers. Whitespace-delimited [A-Za-z][A-Za-z0-9_-]*/ tokens are reserved markers; quoting and escaping are unsupported, following the shared Laplace grammar.

The command resolves the actual stored member through Model, then calls deleteMember. It does not scan or mutate collection views or clean up loans itself. The root permits deletion only when the member has no open loans and removes that member's closed history. Other members, equipment, legacy persons and unrelated loans remain intact. Equal names with distinct NUS IDs remain independent.

Success produces Deleted member: A0123456X and DisplayRequest.members(). Unknown IDs and open-loan references produce CommandException with an identity-specific message and the domain cause. Rejection preserves all model data. Return outstanding equipment before retrying a blocked deletion.

Integration handoff

  • Public constructor: MemberDeleteCommand(NusId nusId).
  • Parser: MemberDeleteCommandParser implements Parser<MemberDeleteCommand>; pass the argument remainder only, such as nus/A0123456X.
  • Shared dependencies are merged: display/Logic #80, parsing/sorting #83 and UI foundation #81.
  • This component PR starts from team master 6230007d781478bc2a740a73fce6036e8a534996.
  • Duy activates member delete and updates routing expectations. Keith's shell consumes the typed directory request and handles identity selection recovery after deletion.

Command classes never save. Once routed, the existing LogicManager parse/execute/save pipeline owns persistence. A failed parse/command must not reach saving; an I/O save failure must be reported and does not promise rollback of an already changed in-memory model. This PR's direct parser/command/JSON round trips save explicitly to temporary files and reload a fresh ModelManager. They do not prove that the unactivated route reaches saving.

Verification

Tests cover normalized IDs, same-name records, actual stored-entity delegation, null misuse, unknown/deleted identities, blocked open loans with existing closed history, permitted deletion and removal of only related history, and preservation after JSON reload. Invalid inputs are interleaved with a return and valid deletions to check subsequent state. Legacy persons and unrelated open loans are retained. No saved user data is read or overwritten.

Run the focused component checks with Java 25:

./gradlew test --tests '*MemberDeleteCommand*' --tests '*LaplaceDeletionIntegrationTest'

Run the full normal ./gradlew check coverage shadowJar and ./.github/run-checks.sh before handoff. Final routed pipeline and GUI deletion/selection tests remain pending.
